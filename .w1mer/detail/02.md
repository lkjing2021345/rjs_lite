# Task 02: Expand Standard Library (Remaining Array/Object/String Methods)

## Approach

All builtin methods in RJS are registered in `src/interpreter.rs` via `install_builtins()` and dispatched in the `call_native()` match arm (lines ~1604–3120). The pattern is:

1. **Registration**: Use `Self::define_non_enumerable(&proto, "methodName", self.native_method("MethodName"))` to register the method name → native function mapping.
2. **Dispatch**: Add a match arm in `call_native()` with the full method name (e.g., `"String.prototype.match"`) that implements the ECMAScript behavior.

The `call_native()` function receives:
- `name`: The full method name string (e.g., `"Array.prototype.at"`)
- `args`: The arguments passed to the method
- `this_value`: The `this` binding (the object the method is called on)
- `construct`: Whether this is a constructor call

For string methods, `this_value` is typically a `Value::String(s)` or `Value::Object(o)` with a `"value"` property. The helper `self.this_str(&this_value)` extracts the string.

For array methods, `this_value` is a `Value::Object(o)` with `Internal::Array(items)`.

For object methods, `this_value` is a `Value::Object(o)`.

## Methods MISSING

### 1. Array.prototype.at(index) — MEDIUM
- **Spec**: ES2022. Accepts an integer index (positive or negative), returns element at that index. Negative indices count from the end. Returns `undefined` if out of bounds.
- **Implementation**: Extract `index` from `args[0]`, handle negative indices like `length + index`, clamp to array bounds.
- **Risk**: Low. Similar to existing `indexOf`/`slice` bound handling.
- **Dependencies**: None.

### 2. String.prototype.at(index) — MEDIUM
- **Spec**: ES2022. Accepts an integer index, returns the code unit at that position. Negative indices count from the end. Returns `""` if out of bounds.
- **Implementation**: Use `self.this_str()`, handle negative indices, return single character or `""`.
- **Risk**: Low. Similar to existing `charAt` but with negative index support.
- **Dependencies**: None.

### 3. String.prototype.match(regexp) — MEDIUM
- **Spec**: ES2020/ES2024. Accepts a regex or string. If string, coerces to regex. Returns array of matches or `null` if no match. With `g` flag, returns array of match strings; without `g`, returns first match with groups.
- **Implementation**: This is the most complex missing method. Needs to either call `RegExp.prototype.exec` (preferred) or implement matching inline. The existing `RegExp.prototype.test/exec` already does basic matching.
- **Risk**: Medium. Requires coordinating with RegExp exec semantics. ES2020 changed `match` to use `Symbol.matchAll` when `g` flag is present.
- **Dependencies**: `RegExp.prototype.exec` (already implemented).

### 4. String.prototype.replaceAll(searchValue, replaceValue) — MEDIUM
- **Spec**: ES2021. Replaces ALL occurrences of `searchValue` with `replaceValue`. Like `replace` but global. If `searchValue` is a string, replaces all occurrences. If a regex with `g` flag, replaces all matches.
- **Implementation**: Iterate through the string finding all occurrences of the needle, building a result string. Handle replacement string special sequences (`$&`, `$'`, `$'`, `$$`).
- **Risk**: Medium. Replacement string special sequences are tricky (`$&` = matched text, `$$` = literal `$`, `$'` = text after match, `$`` = text before match).
- **Dependencies**: None.

### 5. String.prototype.localeCompare(other) — LOW
- **Spec**: ES3+. Compares two strings according to locale-specific rules. In a minimal interpreter without ICU, can fall back to simple code point comparison.
- **Implementation**: Compare string code points lexicographically. Return -1, 0, or 1.
- **Risk**: Low. Simple lexicographic comparison is sufficient for a minimal interpreter.
- **Dependencies**: None.

### 6. Object.fromEntries(entries) — LOW
- **Spec**: ES2019. Takes an iterable of [key, value] pairs and returns a new object with those key-value pairs.
- **Implementation**: Accept an object/array of pairs. Iterate and insert into a new plain object.
- **Risk**: Low. Simple iteration and assignment.
- **Dependencies**: None.

### 7. Object.defineProperties(obj, properties) — LOW
- **Spec**: ES5. Like `defineProperty` but for multiple properties at once.
- **Implementation**: Accepts an object with descriptor properties. Iterate over descriptors and call `defineProperty` for each.
- **Risk**: Low. Reuses existing `Object.defineProperty` dispatch.
- **Dependencies**: `Object.defineProperty` (already implemented).

### 8. Number.isSafeInteger(n) — LOW
- **Spec**: ES6. Returns `true` if value is a number that is an integer within the safe integer range (-2^53+1 to 2^53-1).
- **Implementation**: Check `isFinite`, `fract() == 0.0`, and within `MIN_SAFE_INTEGER`..`MAX_SAFE_INTEGER` range.
- **Risk**: Low. Simple numeric checks.
- **Dependencies**: None.

### 9. String.prototype.codePointAt(pos) — LOW
- **Spec**: ES6. Like `charCodeAt` but returns the full Unicode code point (handling surrogate pairs). Returns `undefined` if out of bounds.
- **Implementation**: Similar to `charCodeAt` but handle UTF-16 surrogate pairs (if current char is in the high surrogate range 0xD800-0xDBFF and next is low surrogate 0xDC00-0xDFFF, combine them).
- **Risk**: Low-Medium. Surrogate pair handling adds a bit of complexity.
- **Dependencies**: None.

### 10. String.prototype.search(regexp) — LOW
- **Spec**: ES3+. Returns the index of the first match of the regex, or -1 if no match.
- **Implementation**: Convert regex to string pattern, use existing `find`/`rfind` on the string.
- **Risk**: Low. Similar to existing `indexOf`/`lastIndexOf` implementations.
- **Dependencies**: None.

### 11. String.prototype.substring vs slice edge cases — LOW (already implemented, verify)
- Already implemented. No action needed.

### 12. Number.prototype.toExponential/fractionDigits/toPrecision — LOW
- **Spec**: ES6+. Additional Number formatting methods.
- **Implementation**: These are lower priority. `toExponential` formats in scientific notation, `toPrecision` formats to a specific precision.
- **Risk**: Low-Medium. String formatting logic.
- **Dependencies**: None.

## Change Surface

- **Only file to modify**: `src/interpreter.rs`
  - `install_builtins()`: Add registration lines for each new method
  - `call_native()`: Add match arms for each new method implementation

## Expected Value

Completing these methods will bring the RJS standard library to ~95% coverage of commonly-used ECMAScript Array, Object, String, and Number methods. This enables:
- Full compatibility with modern JS libraries that use `.at()`, `.replaceAll()`, `Object.fromEntries()`, `Number.isSafeInteger()`
- Unicode-aware string operations (`codePointAt`)
- Locale-aware string comparison (`localeCompare`)
- Complete regex integration (`match`, `search`)
- Multi-property object definition (`defineProperties`)

The remaining gaps after this task would be:
- `Number.prototype.toExponential`, `toPrecision`, `toString` with radix
- `Symbol` well-known symbols and advanced usage
- `Set`, `WeakSet`, `Map` iteration methods (`keys`, `values`, `entries`, `clear`)
- `Promise`, `AsyncFunction`, generators
- `Array.prototype.flat` with depth > 1 (already supported)
- Full `Symbol.match`/`Symbol.replace`/`Symbol.split`/`Symbol.search` protocol

## Risk List

| Risk | Method | Mitigation |
|------|--------|------------|
| Replacement string special sequences | `replaceAll` | Follow ES spec for `$&`, `$$`, `$'`, `$`` |
| Surrogate pair handling | `codePointAt` | Check high/low surrogate ranges explicitly |
| ES2020 `match` with `g` flag | `match` | Use `Symbol.matchAll` for global regex, delegate to existing `exec` |
| Negative index edge cases | `at` (Array/String) | Use same clamping logic as existing `slice`/`indexOf` |
| `fromEntries` with non-iterable | `fromEntries` | Check for `entries`/`values`/`keys` iterator protocol or fall back to array |

## Implementation Notes

1. **Registration pattern**: Add to `install_builtins()` alongside existing methods:
   ```rust
   Self::define_non_enumerable(
       &self.array_proto,
       "at",
       self.native_method("Array.prototype.at"),
   );
   ```

2. **Dispatch pattern**: Add to `call_native()` match:
   ```rust
   "Array.prototype.at" => {
       let index = args.first().map(|v| v.to_number()).unwrap_or(0.0);
       // ... implementation
   }
   ```

3. **String methods** should use `self.this_str(&this_value)` to extract the string, consistent with existing implementations.

4. **All new methods** should be registered as non-enumerable properties on the appropriate prototype, matching the existing convention.

5. **Tests**: The existing test module at the bottom of `interpreter.rs` should be extended with test cases for each new method.
