## 1. Methodology and the sampling caveat (read first)

`run_test262.py::collect()` (lines 105–121) walks `test262/test`, then
`main()` applies `files[:limit]` (line 274–275). With `--category language
--limit 1000` the window is therefore the **first 1000 files under
`test262/test/language`** in file-system walk order. On this checkout that is
exactly:

| Subdir | Files in window |
|--------|----------------:|
| `arguments-object` | 263 |
| `asi` | 102 |
| `block-scope` | 145 (incl. `syntax` 113) |
| `comments` | 52 |
| `computed-property-names` | 48 |
| `destructuring/binding` | 19 |
| `directive-prologue` | 62 |
| `eval-code` | 309 (`direct` 286, `indirect` 23) |
| **Total** | **1000** |

### 1.1 Runner defect inflating `negative-phase-mismatch`

`run_test262.py` builds strict-mode code as
`parts = [STA, ASSERT, …includes, body]` and then sets
`body = '"use strict";\n' + src` (lines 162–171). The requirement directive is
therefore **not** at the start of the concatenated Program — it is preceded by
the harness. Both `Parser::program()` (`src/parser.rs:40–56`, checks only
`statements.first()`) and `Interpreter::detect_strict_mode()`
(`src/interpreter.rs:978–984`) then miss it.

Consequence: `onlyStrict` tests that should fail at **parse** time run
successfully, hit `$DONOTEVALUATE()` from the harness, and are reported as
`negative-phase-mismatch`. Fix (infra, **S**): emit `"use strict";` as the very
first line of the program:

```python
code = ('"use strict";\n' if mode == "strict" else "") + "\n".join(parts)
```

This is a *methodology* fix, but it is cheap and improves signal on all
strict-negative tests. It is a prerequisite for measuring A2/A4 correctly.

### 1.2 Sampling improvements (infra, **S–M**)

- Add `--path SUBSTR` so subtrees can be measured directly (the per-cluster
  numbers above needed an ad-hoc harness to obtain).
- Switch `--limit` to a deterministic **stratified** sample (proportional
  across top-level categories) so the headline number stops depending on
  `os.walk` order (already flagged as R_04 finding #3).
- The runner never verifies the negative `type`; that is documented and can
  stay.

## 2. Measured failure map (1000-test window)

Per-subtree pass/fail and failure-category, from an exact re-run:

```
arguments-object           55 fail  (top-level 18, mapped 36, unmapped 1)  all runtime-error
asi                         4 fail  (S7.9.2_A1_T4, S7.9_A1, A2, A3)        runtime-error
block-scope/syntax         97 fail  (95 negative-phase-mismatch, 2 runtime)
comments                    6 fail  (3 parse, 1 runtime, 1 neg-phase, 1 = S7.4_A6 parse)
computed-property-names    23 fail  (basics 3, class 12, object 4, side-effects 4) runtime
destructuring/binding       4 fail  (3 runtime, 1 parse)
directive-prologue         24 fail  (runtime + neg-phase)
eval-code/direct          196 fail  (193 runtime, 1 parse, 2 negative-but-passed)
eval-code/indirect          9 fail  (runtime)
block-scope/shadowing       1 fail  (runtime)
```

Root causes, confirmed by reading the failing tests:

1. **`arguments` in direct eval** (`eval-code/direct`, 196). e.g.
   `const f = (arguments, p = eval("var arguments = 'param'")) => {}` must throw
   `SyntaxError` when `f` is called (sec-evaldeclarationinstantiation). The
   engine's `eval` (`src/interpreter.rs:3338–3364`) freely declares
   `var arguments`, so `assert.throws(SyntaxError, f)` fails.
2. **Lexical static early errors** (`block-scope/syntax`, 95). Generated matrix
   of `{ var f; let f }`, `{ let f; var f }`, `{ class f {}; var f; }`,
   `function x(){ { class f{}; var f } }`, plus `for (let x, y in {})` and
   `for (let x = 3 in {})`. All expect parse-phase `SyntaxError`. The parser
   has no lexical/var redeclaration analysis.
3. **Mapped `arguments`** (`arguments-object`, 55). `arguments[i]` must alias the
   i-th parameter (writes both ways), `delete arguments[i]` must break the alias
   and clear the element, and descriptors must reflect that. Today
   `arguments` is a plain `Internal::Array` (`src/interpreter.rs:3078–3097`);
   `delete` removes from `props`, leaving the array slot intact
   (`src/interpreter.rs:2379–2399`).
4. **Strict mode** (`directive-prologue`, 24). Three distinct bugs:
   - non-strict `this` for `foo.call(undefined)` must be coerced to the global
     object; the engine passes `this_value` straight through
     (`src/interpreter.rs:3026–3043`, esp. 3039). `14.1-3-s.js` fails on this.
   - directive-prologue detection is too naive (`detect_strict_mode` checks only
     `statements.first()` and skips empty statements); `14.1-16-s.js`
     (`; 'use strict';`) is wrongly treated as strict.
   - strict reserved words in eval (`eval("'use strict'; var public = 1")` must
     throw SyntaxError) — `10.1.1-11-s.js`.
5. **Symbol + `ToPropertyKey`** (`computed-property-names`, 23). `basics/symbol.js`
   needs a real `Symbol` and `Object.getOwnPropertySymbols`; the
   `to-name-side-effects/*` tests need `ToPropertyKey` to call `valueOf` (then
   `toString`) with correct ordering (`value.rs:173–206` returns `Undefined`
   instead of invoking the methods).
6. **Lexer line terminators / hashbang** (`comments`, 6). A block comment
   containing LS/PS/CR must count as a LineTerminator for ASI; single-line
   comments must accept every non-terminator code point; hashbang is illegal in
   `Function`/`eval` source.

## 3. Tier A — fixes for the current 1000-test window

Ordered by measured impact. Effort scale: **S** ≤ ½ day, **M** 1–2 days,
**L** 3–5 days (single implementer, incl. VM parity + tests).

### A1 — Direct-eval `arguments` declaration early errors — **L — +196**

- **Unblocks:** `language/eval-code/direct` (196), part of `eval-code/indirect`.
- **Files:**
  - `src/interpreter.rs:3338–3364` (`"eval"` arm): before executing, detect a
    `var arguments` declaration (or binding named `arguments`) in the eval body;
    throw `SyntaxError` when the caller function's parameter list names
    `arguments`, has a non-simple parameter list, or already has an `arguments`
    binding.
  - `src/interpreter.rs:3063–3097`: function setup must record parameter names
    and the "arguments binding exists" fact somewhere reachable from eval.
    Add a small struct to `Env` (e.g. a per-call `FunctionScope` flag) or store
    param names on the closure env under a reserved key.
  - `src/parser.rs` param handling (`params` 687–711): already returns
    `Vec<Pattern>`; expose identifier names for the check.
  - VM parity: `src/vm.rs:800–931` (`call`/`bind_pattern`) and the `eval` path
    (routed through `call_native`, so only the interpreter eval arm needs the
    check).
- **Note:** all 196 are `runtime-error` today because the assertion
  (`assert.throws`) fails, so the fix is self-contained on the eval path.

### A2 — Lexical redeclaration static early errors — **M — +95**

- **Unblocks:** `language/block-scope/syntax/redeclaration` (95),
  `block-scope/syntax/for-in` (`disallow-multiple-lexical-bindings`,
  `disallow-initialization-assignment`).
- **Design:** a post-parse (or during-parse) early-error pass over each
  `Block`/function body computing `LexicallyDeclaredNames` and
  `VarDeclaredNames`; report `SyntaxError` on intersection. Also validate
  `for (let x, y in …)` (multiple lexicals) and `for (let x = 3 in …)`
  (initializer in for-in/of head).
- **Files:**
  - `src/parser.rs`: new pass + call from `program()` (40), `block()` (665),
    `function_body()` (676), `for_stmt()` (502–570).
  - `src/ast.rs`: `Stmt` already carries everything needed
    (`VarDecl`/`VarDecls`/`FunctionDecl`/`ClassDecl`); a `Stmt::Block` walker is
    sufficient. No `value.rs`/VM change.
- **Impact:** the 95 tests are one generated matrix — a single correct pass
  clears nearly all of them.

### A3 — Mapped `arguments` object + `delete`/descriptor correctness — **L — +55**

- **Unblocks:** `arguments-object/mapped` (36), top-level `10.5-*`/`10.6-*`
  (18), `arguments-object/unmapped` (1).
- **Root cause:** `arguments` is `Internal::Array` with no parameter mapping;
  `delete arguments[i]` clears `props` but not the array slot.
- **Files:**
  - `src/value.rs:23–59`: add mapping metadata to `Object` (e.g.
    `arguments_map: HashMap<usize, String>` naming the aliased parameter, plus a
    `is_mapped_arguments` flag), or a dedicated `Internal::Arguments { slots,
    mapped }`.
  - `src/interpreter.rs:3078–3097`: build the mapped object in sloppy mode
    (parameters present, no non-simple param list, no rest/defaults); leave
    strict mode unmapped.
  - `src/interpreter.rs:2379–2399`: `delete` on an index must remove the map
    entry and clear the slot, returning `true` only if it existed.
  - `src/interpreter.rs` index read/write paths (`Expr::Index` read ~1938,
    `assign_target` 2658–2684, `write_property` 2685): route index 0..n through
    the map so writes update the parameter binding in both directions.
  - `src/interpreter.rs:2791–2876` (`data_descriptor`,
    `get_own_property_descriptor`) and `defineProperty` in `call_native`:
    mapped indices report non-configurable while mapped.
  - VM parity: `src/vm.rs:932` (`bind_pattern`) and its args-object build site
    (mirror of interpreter) — grep `arguments` build in `vm.rs`.
- **Sub-cluster `mapped/Symbol.iterator.js`** additionally needs A5/B1.

### A4 — Strict-mode completeness — **M — +24 now, broad later**

- **Unblocks:** `language/directive-prologue` (24), and removes a large class of
  future `negative-phase-mismatch` / runtime errors (strict reserved words,
  strict `this`, `with`, duplicate params, `eval`/`arguments` assignment).
- **Sub-items (independent, ship incrementally):**
  1. **Non-strict `this` coercion** — `src/interpreter.rs:3026–3043` (line 3039):
     if not strict and not construct and `this_value` is `Undefined`/`Null`,
     substitute `self.global`. Fixes `14.1-3-s.js` family. **S**
  2. **Directive-prologue correctness** — `src/interpreter.rs:978–984`:
     iterate the leading run of string-literal expression statements, stop at the
     first non-directive (and treat an empty statement as terminating the
     prologue); track strict per function body (push/pop around
     `eval_statements`), not just once. **S–M**
  3. **Strict reserved words** — `src/parser.rs` (strict flag at 34,
     reserved-word tables ~1689/1897): reject `public/static/implements/…` in
     strict binding positions, in both function bodies (`function_body` 676) and
     eval. Requires per-function strict tracking in the parser. **M**
  4. **Strict eval** — `src/interpreter.rs:3338–3364`: propagate the strict
     directive from eval source and enforce the same early errors. **M**
  5. **Runner prefix fix** (§1.1) to make `onlyStrict` parse-negative tests
     observable. **S**

### A5 — `Symbol` primitive + well-known symbols — **L — +~10 now, +~/100+ broader**

- **Unblocks now:** `computed-property-names/basics/symbol`, `class/**/symbol`,
  `object/**/symbol`, `to-name-side-effects/*` (≈10–12 in-window).
- **Unblocks broadly:** `built-ins/Symbol` (98), `built-ins/Object`
  (`getOwnPropertySymbols`, symbol-keyed descriptors), iterator protocol,
  `Symbol.iterator`/`toPrimitive`/`toStringTag`/`species`, `for...of`.
- **Architectural note (critical):** `Object.props` is
  `HashMap<String, Value>` (`src/value.rs:24`) and every key path (`resolve_key`
  `interpreter.rs:1754`, compiler `Constant::Key`) is string-based. Real symbols
  require either a dedicated symbol-keyed map on `Object` or a
  `PropertyKey` enum. This is the single largest change in Tier A.
- **Files:** `src/value.rs` (Value + Object + key type), `src/lexer.rs`/
  `src/parser.rs` (`Symbol(...)` call is just an identifier call — no syntax),
  `src/interpreter.rs:861–868` (replace the `"Symbol.iterator"` string stubs
  with real symbols) and `install_builtins` registration of `Symbol`,
  `Symbol.for/keyFor`, `Object.getOwnPropertySymbols` (new, near 381–385),
  `src/compiler.rs`/`src/bytecode.rs` (if a symbol constant is added).

### A6 — `ToPropertyKey` / `ToPrimitive` call semantics — **M — +~8 now, broad**

- **Unblocks:** `computed-property-names/to-name-side-effects` (4),
  `object`/`class` computed-key ordering, and helps `language/types`.
- **Files:** `src/value.rs:173–206` (`to_primitive`) currently returns
  `Undefined` when a `valueOf`/`toString` property exists instead of invoking
  it. Implement `ToPrimitive` (valueOf → toString, with correct ordering and
  `Symbol.toPrimitive` once A5 lands); `src/interpreter.rs:1754` (`resolve_key`)
  and the object-literal computed-key path should call it to produce the string
  key. This requires `to_primitive` to be able to call back into the
  interpreter (it is a `Value` method today) — move the call to
  `Interpreter::to_property_key`.

### A7 — Lexer: comment/line-terminator correctness — **S — +6**

- **Unblocks:** `comments/S7.4_A5`, `S7.4_A6`,
  `multi-line-asi-line-separator/-paragraph-separator`, hashbang-in-Function.
- **Files:** `src/lexer.rs:30–47` (hashbang/line terminators) and the block/line
  comment scanners (~around the `"unterminated block comment"` error at 357).
  A block comment must set the "saw line terminator" flag (affecting ASI) when
  its body contains LF/CR/LS/PS; line comments must accept every
  non-LineTerminator code point. Also reject hashbang inside `Function`/`eval`
  source (the lexer currently allows it at `src/lexer.rs:33–39` unconditionally
  — gate it on "program start").

### A8 — ASI restricted productions — **S — +4**

- **Unblocks:** `asi/S7.9.2_A1_T4`, `S7.9_A1`, `S7.9_A2`, `S7.9_A3`.
- **Files:** `src/parser.rs` ASI logic (restricted productions: `return`/`throw`/
  `break`/`continue`/postfix `++`/`--` newline rules; note `throw` handled at
  `parser.rs:410`). Read the four failing tests for exact expectations.

## 5. Prioritised execution order

1. **Infra:** runner strict-directive position fix + `--path` filter (§1.1–1.2). S.
2. **A4.1–A4.2** (strict `this` coercion + directive-prologue correctness). S–M, +~15.
3. **A2** lexical redeclaration early errors. M, +95.
4. **A1** direct-eval `arguments` early errors. L, +196.
5. **A3** mapped `arguments` + delete/descriptors. L, +55.
6. **A7 + A8** lexer/ASI. S, +10.
7. **A6** `ToPrimitive`/`ToPropertyKey`. M, +8 now / broad.
8. **A4.3–A4.4** strict reserved words + strict eval. M, +~9 now / broad.
9. **A5** `Symbol` (+ symbol-keyed properties architecture). L, +~10 now / +100 broad.
10. **B1** `for...of` + Iterator protocol. L, biggest full-suite unlock.
11. **B4** Map/Set/Weak* → **B2** classes → **B3** Proxy/Reflect → **B5** BigInt → **B6** Date/JSON → **B7** coercion → **B8** TypedArray.

Steps 1–8 target **≈ +370 of the 420 failures** in the current window. Step 9
unlocks the symbol-dependent remainder (~12) and the built-ins window.

## 6. Measurement protocol (for the implementer)

- Reproduce the baseline: `python run_test262.py --category language --limit 1000`
  → must show `pass=580 fail=420 pass_rate=58.0` before changes.
- After each item, re-run the same command and diff `test262_report.json`
  `category_breakdown` + `failure_categories`.
- For per-subtree attribution, temporarily use the ad-hoc harness (import
  `run_test262` and call `collect()` + `run_one()` on `files[:1000]`, grouping by
  the first two path components) — or land the `--path` filter first.
- **Do not** measure with a fresh random sample until §1.2 lands; otherwise the
  number will move for sampling reasons, not code reasons.

## 7. Risks / notes

- **A5 is architectural** (`HashMap<String, Value>` keys); scope it before
  committing to it. `computed-property-names` symbol tests and iterators both
  depend on it.
- **A1/A3 touch the same `arguments` machinery**; sequence A1 → A3 to avoid
  rebasing one against the other.
- **VM parity:** every language-level change must be mirrored in `src/vm.rs`
  (`execute` 457, `call` 800, `bind_pattern` 932, `make_class` 979); the
  existing `cargo test vm::` suite is the guard (see `run_vm_tests.bat`).
- The current window is **not** representative; treat the 58.0% headline as
  "first-1000-language pass rate", not a suite-wide rate.
