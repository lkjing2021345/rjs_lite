# Task 04: Set up test262 subset runner with pass-rate tracking

## Approach

`run_test262.py` is a self-contained stdlib-only Python runner (no third-party
deps — see CONVENTIONS). It walks `test262/test/**/*.js`, skips
`*_FIXTURE.js`, parses the `/*--- ... ---*/` frontmatter, prepends the
harness (`sta.js` + `assert.js` + includes), and runs every required mode
(nonstrict/strict) through `target/release/rjs_lite.exe` in a thread pool.

## What already works

- Walk + frontmatter parsing + harness prepending
- Positive/negative/async mode logic
- Per-run 10s timeout
- Summary counts + `test262_result.json`
- Progress print every 2000 tests

## What this task adds (all in `run_test262.py`)

1. **CLI args** (argparse, stdlib only):
   - `-d DIR` — test262 root (default `./test262`)
   - `-b BIN` — engine binary path (default `target/release/rjs_lite.exe`)
   - `--category DIR[,DIR...]` — subset filter by top-level test dir
     (`language`, `built-ins`, `intl`, ...); `--list-categories` lists them
   - `--skip-category DIR[,DIR...]` — subset filter by exclusion
   - `--limit N` — run at most N tests (for smoke runs)
   - `--workers N` — override worker count
   - `--timeout S` — per-run timeout (default 10s)
   - `--out FILE` — report path (default `test262_report.json`)
   - `--quiet` — suppress progress prints
2. **Failure categorization** — every failure is classified into one of:
   `timeout`, `parse-error`, `runtime-error`, `negative-phase-mismatch`,
   `negative-type-mismatch`, `negative-but-passed`, `async-not-complete`,
   `read-error`. The category map is part of the report.
3. **Pass-rate tracking** — `test262_report.json` (gitignored) records:
   `date`, `commit`, `total/pass/fail/skip`, `pass_rate` (pass/(pass+fail) and
   pass/total), per-category failure counts, `top_failed_categories` with
   per-category sample paths, elapsed time, worker count.
   `test262_result.json` is kept for backward compatibility.
4. **Category breakdown** — summary table of pass/fail per top-level
   category (e.g. `language`, `built-ins`) printed and stored in the report.
